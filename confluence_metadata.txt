1. OVERVIEW
================================================================================
This schema forms the raw (Bronze) ingestion layer for the three core retail
banking entities — customer master, account master, and transaction events.
Data originates from multiple source systems (FINACLE, FLEXCUBE, CRM_V2,
UPI_GATEWAY, PAYMENTS_SWITCH, CARD_HOST) and is loaded daily via batch and
near-real-time pipelines.

These tables are the authoritative raw source for downstream Silver and Gold
layer processing, regulatory reporting, and ML feature engineering.

4. TABLE: transaction_raw
================================================================================

Zone          : Bronze (raw — immutable after load)
Source systems: UPI_GATEWAY, PAYMENTS_SWITCH, CARD_HOST, CORE_BANKING
Row count     : ~120 million (sample: 20 rows)
Columns       : 111
Refresh       : Near real-time + daily batch reconciliation
Source file   : transaction_raw_20260324_part01.csv
Primary key   : transaction_id (format: TXN######)
Foreign keys  : account_id -> account_raw.account_id
                customer_id -> customer_raw.customer_id

5. RELATIONSHIPS

================================================================================
6. LINEAGE
================================================================================
customer_raw   : CRM_V2 / MDM -> customer_raw (Bronze)
                 -> customer_silver (Silver — cleansed, PII masked)
                 -> customer_360_gold (Gold — 360 view with all products)

account_raw    : DEPOSIT_SYSTEM / CORE_BANKING -> account_raw (Bronze)
                 -> account_silver (Silver — normalised, validated)
                 -> account_summary_gold (Gold — balance aggregates)
                 -> total_assets_gold (Gold — regulatory capital)

transaction_raw: UPI_GATEWAY / PAYMENTS_SWITCH / CARD_HOST -> transaction_raw (Bronze)
                 -> transaction_silver (Silver — enriched, reconciled)
                 -> txn_daily_gold (Gold — daily aggregates)
                 -> framl_feature_store (Gold — fraud & AML features)

7. DATA QUALITY RULES
================================================================================
customer_raw:
  - customer_id null check: MANDATORY — reject if null
  - email_primary format validation: WARN if not valid email format
  - date_of_birth range check: WARN if DOB > today or < 1900-01-01
  - duplicate_suspect_flag: flag for manual review

account_raw:
  - account_id null check: MANDATORY — reject if null
  - customer_id FK validation: WARN if no matching customer_raw record
  - available_balance null check: WARN
  - account_status value check: reject if not in allowed list

transaction_raw:
  - transaction_id null check: MANDATORY — reject if null
  - account_id FK validation: WARN if no matching account_raw record
  - transaction_amount zero check: WARN if amount = 0
  - transaction_date future check: WARN if date > today
